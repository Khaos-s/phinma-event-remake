# PHINMA UI Event: data and access

The authoritative schema is `supabase/sql/001_cite_events.sql`, followed by `002_cleanup_unsubmitted_images.sql`. Both have been applied to hosted Supabase. Add new numbered migrations; do not edit these applied definitions to change production.

## Identity and roles

Supabase Auth owns user IDs, credentials, and sessions. `public.role_assignments` has one row per privileged user: `user_id UUID PRIMARY KEY REFERENCES auth.users(id) ON DELETE CASCADE`, and `role TEXT` constrained to `cite_organizer` or `event_admin`.

Authenticated accounts can read only their own role row. Browser roles have no insert/update/delete grant. A valid account with no assignment has member access in the application. User metadata is never an authority for roles.

## Events

| Field | Rule |
| --- | --- |
| `id` | UUID primary key, generated by Postgres |
| `created_by` | Required Auth user reference |
| `title` | Trimmed length 1–200 |
| `description` | Trimmed length 1–5,000 |
| `image_path` | Required path starting with the organizer's UUID and `/` |
| `starts_at`, `ends_at` | Required `timestamptz`; end strictly after start |
| `department`, `course` | Pilot constraints: College of Information Technology and BSIT |
| `target_year` | Small integer 1–4, or null for all college years |
| `status` | `pending`, `approved`, or `rejected`; default pending |
| `rejection_reason` | Null except on rejection; trimmed length 1–1,000 |
| `reviewed_by`, `reviewed_at` | Auth reviewer reference and review timestamp; null while pending |
| `created_at` | Database timestamp, default `now()` |

A check constraint ties status to reviewer/time/reason, preventing inconsistent combinations. Partial schedule and pending indexes support public and queue queries; an organizer/creation index supports personal history. Time-based categories are derived, not stored.

## Permissions

| Operation | Visitor/member | Organizer | Administrator |
| --- | --- | --- | --- |
| Read approved event | Yes | Yes | Yes |
| Read pending/rejected event | No | Own only | All |
| Insert event | No | Own, pending only | No |
| Direct update or delete | No | No | No |
| Approve/reject RPC | No | No | Pending events only |
| Assign roles | No | No | Trusted external administration only; no website role editor |

`has_role(text)` looks up the caller's database assignment. `approve_event(uuid)` and `reject_event(uuid, text)` verify `event_admin`, then atomically update only a pending row and record `auth.uid()` as reviewer. Concurrent or repeated decisions fail once the row is no longer pending. Their security-definer access is deliberate: clients have no direct UPDATE grant; functions use an empty search path and restricted EXECUTE grants. Never expose a generic privileged update RPC.

## Images

`event-images` is a private Supabase Storage bucket with a 5 MB limit and JPG/PNG/WebP MIME allowlist. Organizers upload under their own UUID prefix. An organizer can read their images; administrators can read review images. An image linked to an approved event becomes publicly readable through its storage policy. The UI requests expiring signed URLs rather than making the bucket public.

If upload succeeds but event insertion fails, the client attempts removal. Migration 002 permits an organizer to remove only an own image not referenced by an event. A failed cleanup can leave an unreferenced private object; it must not change event submission into a false success.

## Data boundaries

Database constraints and RLS apply even to direct API calls. UI checks give earlier feedback, not authorization. Public queries select approved events; organizer history also filters by `created_by`, even though RLS already hides other organizers' private records. New reports or views must preserve these boundaries and exclude account credentials/personal data.
