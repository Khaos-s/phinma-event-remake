# PHINMA Event — problem brief

## Who

The first primary user is a person authorized to create events for the CITE Council at PHINMA University of Iloilo. A central PHINMA Event administrator reviews submissions so the organizer's event can become public.

## The struggle

The product owner wants an authorized organizer to submit an event once and have it published automatically after one administrator approval. The team's current real-world approval process and its cost have **not yet been observed**. This is a product hypothesis to test with a CITE Council organizer and an administrator, not a claim that today's process fails in a particular way.

## Today's workaround

Unknown. The product owner has not observed an actual CITE Council approval request. Ask the two intended users how they handle one real event today before treating the problem as validated.

## The MVP

An authorized CITE Council organizer submits an event; a PHINMA Event administrator approves it once; the approved event immediately appears on a public website.

## How we'll know it worked

On the live site, a test organizer submits an event, a test administrator sees it in the review queue and approves it, and a visitor without an account sees it in the correct time filter. Both intended roles should then try the flow and tell us whether it matches their actual work.

## Out of scope

- Student registration and rosters.
- Other college councils and programs.
- Email notifications; the administrator uses an in-app review queue.
- Editing an already approved event.

## Glossary

- **Organizer:** A signed-in person granted permission to submit CITE Council events.
- **Administrator:** A signed-in PHINMA Event reviewer who can approve or reject event submissions.
- **Pending event:** A submitted event visible to the organizer and administrator but not the public.
- **Published event:** An approved event visible to everyone.
